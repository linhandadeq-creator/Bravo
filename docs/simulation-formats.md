# Simulation formats: mRNA-LNP, circRNA, saRNA

The construct engine supports three research-simulation formats. All designs
are generated from simulated data and are **not for clinical or human use**.

| Key | Label | Layout |
| --- | ----- | ------ |
| `mRNA-LNP` | Linear mRNA (LNP) | `[5PRIME] [ANTIGEN_...] [3PRIME]` |
| `circRNA` | Circular RNA (PIE) | `[PIE_3P] [IRES] [ANTIGEN_...] [PIE_5P]` |
| `saRNA` | Self-amplifying RNA | `[5PRIME] [REPLICASE] [SGP] [ANTIGEN_...] [3PRIME]` |

## Design rules per format

### mRNA-LNP (default)

Capped, polyadenylated linear mRNA. The 5' UTR is picked from a small library
with the translation-efficiency model (ridge over MPRA features; heuristic
weights until trained). Sequence QC applies the standard release gate:
GC window, homopolymers, restriction sites, cryptic poly(A)/splice signals,
Kozak context, CAI ≥ 0.65, poly(A) ≥ 100 nt, capping criteria.

### circRNA — circular RNA via PIE

- The linear representation opens at the ligation junction (position 0):
  PIE_E1 (3' exon) → IRES → START → antigen ORF → STOP → PIE_E2 (5' exon).
- Circularization is simulated as permuted intron-exon (PIE) self-splicing;
  the SOP adds an RNase R linear-residual digestion step.
- IRES-driven translation: **no cap, no poly(A) tail, no Kozak requirement** —
  the corresponding QC checks are waived with an explicit
  "not applicable" note instead of being silently skipped.
- Release criteria replace capping/poly(A) with circularization purity
  (≥ 90%) and linear-residual limits.

### saRNA — self-amplifying RNA

- Alphavirus-like replicon: 5' UTR → replicase cassette → subgenomic
  promoter (SGP, ending in a Kozak context) → antigen ORF → 3' UTR → poly(A).
- The replicase cassette is a **simulated placeholder** (~600 nt, balanced
  GC, constraint-clean) — not a functional nsp1-4 sequence. It is annotated
  as such in every output.
- Release criteria add a full-length replicon integrity gate (≥ 80%).

## Scaffold elements

`IRES`, `PIE_E1`, `PIE_E2`, `REPLICASE` and `SGP` are deterministic,
seeded, constraint-clean placeholder sequences generated by
`app/blueprint/formats.py`. They are labelled "simulated" everywhere they
appear and are **not functional biological elements**.

## API

- `POST /api/analysis-runs/{id}/constructs` accepts
  `simulation_format` ∈ {`mRNA-LNP`, `circRNA`, `saRNA`}; anything else is
  rejected (`422` for JSON bodies, `400` in the one-click module).
- `POST /api/one-click/generate` accepts `simulation_format` as a form field.
- The blueprint output (`GET /api/constructs/{id}/blueprint`) includes
  `circular` and `ligation_junction` fields and format-specific segments;
  the production package's `sequence_design` embeds the UTR selection and
  its score provenance.

## UTR optimisation scoring

When the format has a 5' UTR, the designer scores every library candidate with
`app/blueprint/utr_model.score()` and selects the best. The choice, score and
model provenance (`heuristic` vs `trained_ridge`) are recorded in
`sequence_design.utr_selection` of the production package.
